## Тема

Тестування з бібліотекою pytest

### Мета роботи

Перевірити поведінку фігур і карткової гри за допомогою pytest, параметризації, фікстур і маркерів.

---

### Виконання роботи

1. У [прикладі викладача](../../example/testing/02_pytest/test_app.py) параметризовано три дозволені фігури. Окремо перевірено невідомі типи, нульові, від’ємні й нечислові значення довжини. Для винятків використано `pytest.raises`.
2. Фікстура `square` створює квадрат завдовжки 10. Фікстуру `allowed_figures` із `scope="module"` використовують два тести. Два тести з маркером `unit` запущено окремо. [Результат](results/02-marker.txt).
3. У [матеріалах занять](tests) перевірено випадки з картами, параметризацію, залежні фікстури, `yield` і обмеження типів. У демонстрації області дії залишено один свідомо пропущений тест. Для тестів атаки зафіксовано випадкове рішення за допомогою `patch`.
4. У тимчасовій копії очікування довжини змінено з 10 на 9. Запуск із `-x --tb=short` зупинився на першому падінні й показав `assert 10 == 9`. [Журнал діагностики](results/02-failure.txt).

```bash
# Із кореня репозиторію
poetry add --group dev pytest
cd example/testing/02_pytest
poetry run pytest -v
poetry run pytest test_app.py::test_triangle_type -v
poetry run pytest -m unit -v
poetry run pytest --collect-only

# Із testing/2_lab
cd ../../../testing/2_lab
PYTHONPATH=src poetry run pytest -v
```

У [прикладі Figure](results/02-teacher-final.txt) пройшло 17 тестів. У [груповому прикладі](results/02-group-final.txt) пройшло 37 тестів і один пропущено. Методи `unittest.TestCase` використовують `self.assertEqual` і життєвий цикл класу. У функціях pytest достатньо `assert`, а підготовлені дані передаються через аргументи-фікстури.

---

### Висновок

Мету досягнуто. Параметризація дала окремий результат для кожного набору. Спільний запуск і запуск за маркером показали, які тести вибирає pytest. Для діагностики зручно залишати короткий traceback та назву конкретного тесту.
